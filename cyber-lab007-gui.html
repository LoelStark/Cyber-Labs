01 Briefing

You will learn to perform a systematic vulnerability assessment using Nmap and Python. You will scan a target, enumerate services, detect vulnerabilities with Nmap Scripting Engine (NSE), parse scan results programmatically, and produce a structured vulnerability report. This lab teaches you that vulnerability assessment is not just running a scanner — it is understanding what the scanner tells you, verifying findings, and communicating risk to stakeholders.

02 Concept Primer

Read before starting — these ideas frame every task below.

Nmap
is a network scanner that discovers hosts and services on a network. It sends packets and analyses responses to determine what is running.
Nmap Scripting Engine (NSE)
extends Nmap with Lua scripts that perform tasks like vulnerability detection, service enumeration, and brute-force attacks.
Service version detection
(-sV) probes open ports to determine what software is running and its version. Critical for vulnerability assessment.
Vulnerability assessment
is the process of identifying, classifying, and prioritising vulnerabilities. Different from penetration testing — you are finding weaknesses, not exploiting them.
False positives
are common in vulnerability scanning. A scanner says "vulnerable" but the system is actually safe. You must verify findings manually.

03 Tasks — do these in order

Write down every command you run and its key output — your deliverable depends on the evidence, not on the answers. Click a command block to copy it.

1 · Identify the target · Phase 1: Host Discovery (10 min)
Confirm what is listening on your machine. Note the IP address and open ports. For this lab, 127.0.0.1 (localhost) is your target.
ss -tlnp
2 · Run a host discovery scan · Phase 1: Host Discovery (10 min)
Ping sweep to confirm the host is up. Record the result.
nmap -sn 127.0.0.1
3 · Run a quick port scan · Phase 1: Host Discovery (10 min)
Find open ports. Note which ports are open and what services Nmap thinks they are. This is the "low-hanging fruit" scan.
nmap 127.0.0.1
4 · Run a service version scan · Phase 2: Service Enumeration (20 min)
Identify what software is running on each open port. Record the service name, version, and any additional information Nmap provides.
nmap -sV 127.0.0.1
5 · Run an aggressive scan · Phase 2: Service Enumeration (20 min)
Combine service detection, OS detection, and traceroute. Note additional details: OS guess, service banners, and any script results.
nmap -A 127.0.0.1
6 · Scan all ports · Phase 2: Service Enumeration (20 min)
Nmap by default scans only the top 1000 ports. Scan all 65535. Did you find any additional ports? Record them.
nmap -p- 127.0.0.1
7 · Targeted port scan · Phase 2: Service Enumeration (20 min)
If you found a web server (port 80 or 8080), scan it in detail. This reveals directories, titles, and allowed HTTP methods.
nmap -sV -p 8080 --script=http-enum,http-title,http-methods 127.0.0.1
8 · Run vulnerability detection scripts · Phase 3: Vulnerability Detection (25 min)
Use NSE scripts to check for known vulnerabilities. The vulners script checks service versions against the CVE database. Record any CVEs found.
nmap -sV --script=vulners 127.0.0.1
9 · Run category-specific scripts · Phase 3: Vulnerability Detection (25 min)
Target specific vulnerability types. Replace the script categories with services relevant to your target.
nmap -sV --script=ftp-anon,ssh-auth-methods,smb-vuln-* 127.0.0.1
10 · Brute-force check (if applicable) · Phase 3: Vulnerability Detection (25 min)
If you found an SSH service, test if weak credentials are accepted. Use minimal attempts to avoid locking accounts.
nmap -sV --script=ssh-brute --script-args userdb=/dev/null,passdb=/dev/null 127.0.0.1
11 · Save scan output in XML format · Phase 3: Vulnerability Detection (25 min)
XML format allows programmatic parsing. This is critical for later analysis.
nmap -sV -A --script=vulners -oX scan-results.xml 127.0.0.1
12 · Write a Python script to parse the XML output · Phase 4: Python Analysis and Reporting (25 min)
Create parse_scan.py — extracts host, ports, services, and vulnerabilities from the XML. Run it and verify the JSON output.
python3 parse_scan.py
13 · Generate a vulnerability report · Phase 4: Python Analysis and Reporting (25 min)
Extend your Python script to create a Markdown report with a findings table.
14 · Add CVE lookup · Phase 4: Python Analysis and Reporting (25 min)
For each vulnerability found, look up CVE details using the CIRCL API.
15 · Verify findings · Phase 5: Verification and Reporting (10 min)
For each vulnerability: Is this a false positive? What is the actual risk? What is the recommended fix?
16 · Complete the deliverables · Phase 5: Verification and Reporting (10 min)
Produce all five deliverable files.
