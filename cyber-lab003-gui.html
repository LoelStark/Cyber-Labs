02 Concept Primer

Read before starting — these ideas frame every task below.

Beaconing pattern
C2 malware does not blast data continuously. It connects on a timer — every 30 seconds, every 5 minutes, jittered to avoid detection. In a pcap, this looks like repeated small packets to the same destination with regular intervals. Regular intervals = automated. Human traffic is irregular.
Payload extraction
A pcap is not a file archive. Extracting the payload means following TCP streams and carving out the data bytes. `tshark` can do this with `--export-objects`. The result may be a script, a binary, or encoded data.
Static analysis before execution
Never run unknown code before you have read it. `file` tells you the format. `strings` pulls readable text. `xxd` gives you the raw bytes. Nine times out of ten, you learn enough to classify the threat without executing it.
Behavioural analysis
If static analysis is inconclusive, run the payload in a sandbox (VM with no network, or a container with `--network none`) and observe: what files does it touch? What does it try to open? Does it fork? Does it try to phone home?
IOCs (Indicators of Compromise)
The specific, observable artefacts that identify this threat: IP addresses, domain names, file hashes, file paths, registry keys, mutex names. IOCs are what you feed into your detection rules. An IOC without a hash is incomplete.
